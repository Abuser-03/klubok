# Клубок — магазин валяных изделий на Go + htmx

Демонстрационный Telegram Mini App: витрина брелков и шарфов ручной валки,
корзина, оформление заказа и запись на мастер-классы. Весь HTML рендерится
на сервере через `html/template`, интерактив — на htmx, анимации — на GSAP.
Своего JS-кода примерно 180 строк, и почти весь он про анимацию, а не про
бизнес-логику.

## Запуск

```bash
go run .                      # http://localhost:8080
BOT_TOKEN=123:AA-xxx go run . # с проверкой подписи Telegram
```

Тесты:

```bash
go test -v ./...
go test -race -run TestCartStore ./...
```

## Что где

| Файл | Отвечает за |
|---|---|
| `main.go` | модель, каталог-заглушка, корзина, хендлеры, проверка `initData` |
| `main_test.go` | тесты подписи Telegram, корзины, форматирования цен |
| `templates/layout.html` | страница целиком |
| `templates/partials/grid.html` | сетка товаров (её же отдаём на фильтр) |
| `templates/partials/cart.html` | корзина, чекаут, ответы формы записи |
| `static/js/app.js` | GSAP, шторка корзины, Telegram SDK |

## Как это устроено

**htmx вместо фронтенд-фреймворка.** Кнопки шлют `hx-post`/`hx-get`, сервер
в ответ отдаёт не JSON, а готовый кусок HTML — тот же `html/template`, только
партиал. Например, `POST /cart/add/{id}` возвращает целиком отрендеренную
панель корзины, а htmx подменяет ей `#cart-panel` через `hx-swap="outerHTML"`.
Никакого состояния на клиенте — источник правды всегда на сервере.

**Счётчик в шапке** обновляется out-of-band: в том же ответе едет второй
элемент с `hx-swap-oob="true"`, и htmx кладёт его по своему `id`, не трогая
основную цель свопа. Так одним запросом обновляются два разных места страницы.

**Проверка `initData`.** Telegram отдаёт в Mini App подписанную строку с
данными пользователя. `VerifyInitData` пересобирает `data_check_string`,
считает двухступенчатый HMAC-SHA256 (сначала секрет из токена бота, потом
подпись) и сравнивает результат через `hmac.Equal` — обычное `==` здесь
уязвимо к атаке по таймингам. Плюс проверяется `auth_date`, иначе однажды
перехваченная строка работала бы вечно. Без `BOT_TOKEN` проверка пропускается,
чтобы можно было гонять локально в браузере.

**Анимации.** Один срежиссированный момент на загрузке: нити шерсти в хиро
прорисовываются через `stroke-dashoffset`, следом поднимаются строки
заголовка. Дальше движение только в ответ на действие — товар улетает в
иконку корзины, шторка выезжает. Карточки проявляются при скролле через
`ScrollTrigger.batch`. Всё выключается по `prefers-reduced-motion`.

## Чего здесь намеренно нет

Каталог и корзина живут в памяти процесса — при рестарте всё обнуляется.
В боевом варианте сюда встают Postgres и Redis, а `handleCheckout` вместо
лога пишет заказ со статусом `pending` и `idempotency_key`, идёт в платёжный
шлюз и ждёт webhook, который переведёт заказ в `paid`.

## Подключение как Mini App

1. У @BotFather: `/newapp`, выбрать бота, указать HTTPS-адрес.
2. Локально поднять туннель (`cloudflared tunnel --url http://localhost:8080`)
   и скормить его адрес BotFather — Telegram не открывает http и localhost.
3. Задать `BOT_TOKEN` перед запуском, иначе подпись не проверяется.
