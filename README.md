# Клубок — магазин валяных изделий на Go + htmx

Демонстрационный Telegram Mini App: витрина брелков и шарфов ручной валки,
корзина, оформление заказа и запись на мастер-классы. Весь HTML рендерится
на сервере через `html/template`, интерактив — на htmx, анимации — на GSAP.
Своего JS-кода примерно 180 строк, и почти весь он про анимацию, а не про
бизнес-логику.

## Запуск

```bash
go run .                      # http://localhost:8080
BOT_TOKEN=123:AA-xxx go run . # с проверкой подписи Telegram
```

Тесты:

```bash
go test -v ./...
go test -race -run TestCartStore ./...
```

## Что где

| Файл | Отвечает за |
|---|---|
| `main.go` | модель, каталог-заглушка, корзина, хендлеры |
| `serve.go` | сжатие ответов и кеширование статики |
| `surface.go` | разделение витрин: опознание, оболочка, оплата |
| `main_test.go` | тесты подписи Telegram, корзины, форматирования цен |
| `templates/layout-web.html` | рама сайта: шапка, хиро, подвал |
| `templates/layout-tg.html` | рама Mini App: без шапки, хиро и подвала |
| `templates/partials/head.html` | общий `<head>` и подключение скриптов |
| `templates/partials/sections.html` | хиро, каталог, мастер-классы |
| `templates/partials/grid.html` | сетка товаров, она же ответ на фильтр |
| `templates/partials/art.html` | SVG-заглушки вместо фотографий |
| `templates/partials/cart.html` | шторка корзины и OOB-счётчик |
| `templates/partials/checkout.html` | подтверждение заказа |
| `templates/partials/signup.html` | ответы формы записи |
| `static/css/fonts.css` | локальные `@font-face`, кириллица и латиница раздельно |
| `static/css/style.css` | палитра, типографика, сетка |
| `static/css/tg.css` | правки только для Mini App |
| `static/js/app.js` | анимации, шторка, Telegram SDK, htmx-хуки |
| `static/js/vendor/` | htmx и GSAP локально, не с чужих CDN |
| `static/fonts/` | woff2 Spectral и Golos Text, только нужные начертания |

Где править что: товары и мастер-классы — срезы `catalog` и `workshops`
в `main.go`, это единственное место с данными. Тексты — `sections.html`
и `grid.html`. Подключить шрифт или библиотеку — `head.html`, обе витрины
подхватят. Различия между сайтом и Mini App — `surface.go`.

Имена шаблонов глобальны: `ParseFS` собирает их по маскам, и два
`{{define}}` с одинаковым именем в разных файлах молча переопределят
друг друга. Шаблоны, которые рендерит Go, сохраняют расширение в имени
(`grid.html`), внутренние фрагменты — нет (`head`, `hero`, `art-scarf`).

`templates/` вшиты в бинарник через `embed`, а `static/` читается с диска:
правка шаблона требует пересборки, CSS и JS подхватываются перезапуском.
Поэтому же в Dockerfile папка `static` копируется отдельной строкой.

## Как это устроено

**htmx вместо фронтенд-фреймворка.** Кнопки шлют `hx-post`/`hx-get`, сервер
в ответ отдаёт не JSON, а готовый кусок HTML — тот же `html/template`, только
партиал. Например, `POST /cart/add/{id}` возвращает целиком отрендеренную
панель корзины, а htmx подменяет ей `#cart-panel` через `hx-swap="outerHTML"`.
Никакого состояния на клиенте — источник правды всегда на сервере.

**Счётчик в шапке** обновляется out-of-band: в том же ответе едет второй
элемент с `hx-swap-oob="true"`, и htmx кладёт его по своему `id`, не трогая
основную цель свопа. Так одним запросом обновляются два разных места страницы.

**Проверка `initData`.** Telegram отдаёт в Mini App подписанную строку с
данными пользователя. `VerifyInitData` пересобирает `data_check_string`,
считает двухступенчатый HMAC-SHA256 (сначала секрет из токена бота, потом
подпись) и сравнивает результат через `hmac.Equal` — обычное `==` здесь
уязвимо к атаке по таймингам. Плюс проверяется `auth_date`, иначе однажды
перехваченная строка работала бы вечно. Без `BOT_TOKEN` проверка пропускается,
чтобы можно было гонять локально в браузере.

**Анимации.** Один срежиссированный момент на загрузке: нити шерсти в хиро
прорисовываются через `stroke-dashoffset`, следом поднимаются строки
заголовка. Дальше движение только в ответ на действие — товар улетает в
иконку корзины, шторка выезжает. Карточки проявляются при скролле через
`ScrollTrigger.batch`. Всё выключается по `prefers-reduced-motion`.

## Чего здесь намеренно нет

Каталог и корзина живут в памяти процесса — при рестарте всё обнуляется.
В боевом варианте сюда встают Postgres и Redis, а `handleCheckout` вместо
лога пишет заказ со статусом `pending` и `idempotency_key`, идёт в платёжный
шлюз и ждёт webhook, который переведёт заказ в `paid`.

## Подключение как Mini App

1. У @BotFather: `/newapp`, выбрать бота, указать HTTPS-адрес.
2. Локально поднять туннель (`cloudflared tunnel --url http://localhost:8080`)
   и скормить его адрес BotFather — Telegram не открывает http и localhost.
3. Задать `BOT_TOKEN` перед запуском, иначе подпись не проверяется.

## Доступность из сетей с ограничениями

Сайт не обращается ни к одному внешнему домену: шрифты, htmx и GSAP лежат
в `static/`. Google Fonts, unpkg и cdnjs доступны не отовсюду, и когда они
молчат, страница остаётся без дизайна и без работающей корзины.

`serve.go` жмёт все текстовые ответы (главная — 24 КБ до, 5.5 КБ после)
и раздаёт кеш-заголовки: шрифты и библиотеки помечены `immutable` на год,
свои стили и скрипты отвечают 304 без тела, если не менялись. Первый заход
весит около 152 КБ на всё, повторный — ноль.

Единственная внешняя ссылка осталась в `layout-tg.html` — SDK Telegram.
Он нужен только внутри мессенджера, где домен Telegram по определению
доступен, и на сайт не влияет.
